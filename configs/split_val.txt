# Committed validation file list (SPEC 6.1, V29).
# NEVER regenerate this at runtime -- that is leakage. This file IS the split.
# Filenames are relative to <data_root>/train/ and name the GT/NoisyLR pair
#   <data_root>/train/GT/<name>  and  <data_root>/train/NoisyLR/<name>.
# NOTE: test_NoisyLR reuses these same filenames for DIFFERENT images. This list refers
# ONLY to train/. See docs/SPEC_ADDENDUM.md section 6.
#
# 400 of 3200 pairs = 12.5% validation, 2800 train. SPEC 6.1 asks for 10-15%.
#
# BLOCK-OF-4 ALIGNED. docs/decisions.md D8 measured a block-of-4 structure in train/:
# four consecutive crops appear to come from one source photograph (within-block descriptor
# distance 1.55-1.60 vs a 1.68 random baseline). A naive random split would therefore LEAK --
# sibling crops of one photograph would straddle train and val. Every entry below is a
# complete block {4b, 4b+1, 4b+2, 4b+3}, so all four crops of a source photo land on the
# same side of the split. 100 whole blocks are held out.
#
# Composition:
#   * blocks 750-799  -> 003000.npy - 003199.npy   (200 files)
#     Exactly the held-out set used for the renormalisation experiment in docs/decisions.md
#     D3, so that measurement stays comparable and re-computable as a subset of this split.
#   * blocks 0,15,30,...,735 -> 50 further blocks spread evenly across the first 750 blocks
#     (200 files), so validation is not confined to the tail of the corpus ordering.
#
# Generated once, by hand, and committed. Do not sort, filter or resample it in code.

# requirements.txt -- complete `pip freeze` of the environment this repo was built in.
# Python 3.12.10, Windows 11, CUDA 12.8, NVIDIA GeForce RTX 4060 Laptop GPU (8 GB).
#
# WHY THE FIRST LINE IS AN INDEX DIRECTIVE
# ----------------------------------------
# `torch==2.11.0+cu128` is a CUDA build. The `+cu128` local version is published ONLY on
# download.pytorch.org, never on PyPI, so the directive below is what makes a bare
#     pip install -r requirements.txt
# resolve it with no extra flags, no env vars and no manual steps.
#
# The pin and the directive are a matched pair, and the pin is the safety catch. Without
# the `+cu128` local version, pip is free to satisfy `torch` from PyPI -- which is exactly
# what happened on this machine while installing lpips (it depends on torch + torchvision):
# pip silently REPLACED the CUDA build with a CPU-only wheel. Nothing failed, nothing was
# logged, and `torch.cuda.is_available()` quietly became False. See docs/decisions.md D18
# and docs/BLOCKERS.md B8. With `+cu128` in the pin there is no CPU candidate to fall back
# to: either the CUDA wheel installs or the install fails loudly. A loud failure is the
# desired behaviour -- a silent CPU install would pass every check while scoring zero on
# the throughput axis.
#
# Verified 2026-08-15: a fresh `py -3.12 -m venv` + `pip install -r requirements.txt`
# (no other flags) yields torch 2.11.0+cu128 / torchvision 0.26.0+cu128 with
# torch.version.cuda == '12.8' and torch.cuda.is_available() == True.
#
# On a machine with no NVIDIA GPU the same wheels install and torch falls back to CPU at
# runtime; inference.py handles that (--device cpu is automatic).

# Qualitative examples — `weights/best.pt` (29.5850 dB checkpoint)

Evidence folder. Every panel here was generated from real, on-disk artifacts — the same
checkpoint (Round 2 Phase 3 structural-content fine-tune, SHA256
`6d74ccfdd72e1271a7de5fdede5c341b3cf18ca4294619dd90a97c0591f66397`) that produced the reported
validation metrics and the final-test submission outputs. Nothing here is synthetic or
hand-drawn. Generated by `scripts/make_qualitative_examples.py` (not part of the verified
pipeline or `scripts/verify_all.py` — it uses `matplotlib`, which `inference.py` may never
import at module level per CLAUDE.md STYLE). Regenerated 2026-08-17 after the Phase 3
checkpoint promotion (`docs/decisions.md` D71/D72) — the prior version of this folder was
rendered against the superseded 29.2548 dB checkpoint and is fully replaced, not appended to.

## What each panel shows

**Validation panels** (`val_*.png`, 6 files) — four images side by side:
`NoisyLR | Restored | GT | |Restored − GT| error map`, titled with the file's own PSNR/SSIM
computed with the exact pinned settings from `src/metrics.py` / `scripts/evaluate.py`
(`skimage` PSNR/SSIM, `data_range=1.0`, `gaussian_weights=True, sigma=1.5,
use_sample_covariance=False`). Source predictions: `results/baselines/final/` (the same
disk-verified predictions directory that produced the reported
29.5850 ± 4.6301 dB / 0.79460 ± 0.14204 / 0.25416 ± 0.13263 numbers over all 400 pairs in
`configs/split_val.txt`). GT/NoisyLR are read from `<data_root>/train/GT` and
`<data_root>/train/NoisyLR`.

The six files below were originally selected under an earlier checkpoint's per-image ranking
(best / strong / typical ×2 / worst / lowest-SSIM-of-worst-8). **Re-checked against the
current checkpoint before reuse, not assumed to still apply**: `002041.npy` is still the
literal worst PSNR in the 400-pair split (rank 0/400) and `000900.npy` is still near-worst
(PSNR rank 3/400); `000960.npy`/`001323.npy` remain in the top 2% by PSNR (rank 398/400 and
392/400); `003167.npy`/`001682.npy` remain mid-pack (PSNR rank 270/400 and 284/400). The tags
below are accurate for this checkpoint, not stale labels carried over unchecked.

NoisyLR panels are **display-clipped to [0,1] for visualization only**; the true on-disk range
(shown in the panel subtitle) legitimately exceeds [0,1] per `docs/io_contract.md` and is

**Documented failure case** (`failurecase_D5_*.png`, 1 file) — `docs/decisions.md` D5
identified `000984.npy` as the honest worst case by direct measurement (80.5% of GT spectral
energy lies above the LR Nyquist limit, i.e. provably unrecoverable by any model), and found
it to be **broadband noise-like texture, not the periodic aliasing grating SPEC §5.4
predicted** — see `results/eda/aliasing_failure_case.png` for the original spectral-energy
figure. `000984.npy` is **not a member of `configs/split_val.txt`** (it was identified by a
separate full-corpus screen, not the held-out split), so its PSNR/SSIM (11.71 dB / 0.3697) is
an **illustrative measurement only** — it is not part of, and does not change, the reported
29.5850 dB validation mean. The restoration was produced by the script issuing a live
`inference.py --require_weights` subprocess call against `weights/best.pt` (the real
production entry point, not a re-implemented forward pass) on a scratch single-file
input/output directory, so nothing about the actual scored split was touched.

**Final-test panels** (`finaltest_*.png`, 5 files) — two images side by side:
`NoisyLR | Restored`, titled in red, explicitly stating **NO GROUND TRUTH** and that no
PSNR/SSIM/LPIPS is computed or claimed. Source: the actual 400-file archive generated for
submission (`results/restored_test_outputs/`, republished as GitHub Release `artifacts-v3`
after this promotion — see that folder's own README for the current archive hash); the local
copy used to render these panels was regenerated fresh with
`inference.py --input_dir <released test_NoisyLR> --require_weights` against the current
`weights/best.pt`. Files chosen spread across the 400-file index (`000000`, `000099`,
`000199`, `000299`, `000399`) for coverage, not cherry-picked for appearance.

## Do not

- Do not read a final-test panel as carrying a quality score — there is no ground truth for
  the released test set, full stop (`docs/decisions.md`, README "Result summary").
- Do not fold the D5 case's 11.71 dB into the reported 29.5850 dB mean — they are computed
  over different, non-overlapping sets of files (400-pair `configs/split_val.txt` vs. one
  out-of-split file).

## Reproduction

```bash
py -3.12 inference.py --input_dir <released test_NoisyLR dir> --output_dir <scratch dir> --require_weights
py -3.12 scripts/make_qualitative_examples.py \
  --data_root <dataset root, contains train/GT and train/NoisyLR> \
  --final_test_lr_dir <released test_NoisyLR dir> \
  --final_test_pred_dir <scratch dir from the inference.py run above>
```

`--data_root` must contain `train/GT` and `train/NoisyLR` (the val split lives inside
`train/`, selected by `configs/split_val.txt`). `--final_test_lr_dir` defaults to
`<data_root>/NoisyLR` if omitted — pass it explicitly when the released test inputs live
elsewhere (e.g. `<data_root>/test_NoisyLR`, this project's actual layout). Pass `--skip_d5` to
skip the extra `inference.py` subprocess call for the D5 panel. Both the manifest's headline
PSNR/SSIM/LPIPS numbers (parsed live from `results/metrics_summary.md`'s "Final model" row)
and the checkpoint sha256 (computed directly from `weights/best.pt` at generation time) are
derived at runtime, not hardcoded — the sha256 constant was itself a hardcoded literal that
went stale across two prior promotions before this fix, a real recurring bug now closed.

The script loads `skimage.metrics.peak_signal_noise_ratio` / `structural_similarity` with the
settings pinned in `src/metrics.py`. It is **not** part of `scripts/verify_all.py` and does
not affect any V-check.
